Bitview

Privacy

Last updated November 23, 2026

What this covers

Every Bitview service run at these two addresses:

  • bitview.space: the website and its apps, the REST API and its OpenAPI description, llms.txt and llms-full.txt, the Agent Skill, which calls the API, and the MCP server, which the Claude Code plugin uses together with the skill.
  • mcp.bitview.space: the MCP server's older address, the same server.

Bitview is open source, and anyone can run it. A server someone else runs is theirs, under their own policy.

Using Bitview asks nothing about you

There are no accounts, API keys, cookies, ads, trackers or analytics scripts. A request carries only what it asks for, in its path and query: series ids, ranges, block hashes, transaction ids or addresses.

Request logs

The bitview.space server logs one line per request: the time, the method, the status, the path with its query, and how long the answer took. It logs no IP address, no user agent and no other detail about who sent the request.

The lines are kept in daily files on the server, which deletes files older than seven days every day. The last 1,000 lines are also public, on the Logs page and at /api/server/logs, so anything in a path or query, an address for example, can be seen there.

The MCP server

The MCP server is part of the bitview.space server. Each tool call is answered by the API request it names, which is logged as one line like any other request, as above: its path and query show on the Logs page too. Nothing else about the call is logged, and the server keeps no sessions and no record of what was asked or answered.

Network providers

Both addresses are served through Cloudflare, which handles every connection, under Cloudflare's privacy policy. Cloudflare keeps a record of each request for about a month, including its IP address, full user agent, path and query. Bitview's operators could query those records. Nothing of Bitview's does, except one script that turns them into the counts published at stats.bitview.space.

Cloudflare passes each visitor's IP address on to Bitview's servers, in the X-Forwarded-For header, and they neither read nor log it. Cloudflare adds no cookie or script to Bitview's pages, except on a check it shows a connection it judges a threat: that page runs Cloudflare's script, and passing it leaves its cf_clearance cookie.

Until November 17, 2026, Cloudflare also added its Web Analytics script to these pages for visitors outside the EU. It recorded each page view with its address and the page it came from, for Cloudflare to keep six months. It was turned off and deleted on November 17, 2026. Its records could still be read right after, and Cloudflare doesn't say whether deleting it drops them.

Published traffic counts

Counts of requests per day and per hour, by country, browser family, status code, route and more, are public, with their full history in a public repository.

  • A path is counted by its route, such as /api/address/:address/txs, never by what it holds.
  • Never published: IP addresses, full user agents, networks (ASNs), query strings or what anyone looked up.

In your browser

Some apps keep settings and recent choices in your browser's storage, such as Studio's charts or when you last opened each app. They stay on your device and are never sent.

One page loads files from elsewhere: the Benchmarks page reads its results from GitHub, which receives the request as for any page it serves.

Email

An email to support@bitview.space is kept, with the address it came from, to answer it and for nothing else. It stays in the mailbox until you ask support@bitview.space to delete it. The mailbox is hosted by Apple's iCloud Mail, under Apple's privacy policy. Issues on GitHub are public, under GitHub's own terms.

Sharing

Nothing is sold. Apart from the providers and counts named above, nothing is shared, and beyond the logs and emails above, nothing is kept to share.

Changes and contact

This page changes when the services do, and its date says when it last did. Its history is in the source. Questions: support@bitview.space, and other ways to get help are on the support page. The terms for using Bitview are on the terms page.
