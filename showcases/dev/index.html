Run Bitview on your own node

Bitview runs beside Bitcoin Core: it indexes the chain, computes its series and serves them to Studio, an HTTP API, generated clients and an MCP adapter. The same server runs bitview.space.

Install Source on GitHub
  • Needs Bitcoin Core, mainnet
  • Linux or macOS
  • About 290 GiB for the default index
  • 16 GiB RAM recommended
  • MIT license

Run it

bitviewd runs the official plugins, Studio and the API. It reads Bitcoin Core's block files and follows the active chain over RPC.

Install, then run
$ rustup update && RUSTFLAGS="-C target-cpu=native" cargo install --locked bitviewd
$ bitviewd

It listens on 0.0.0.0:3110 without authentication. Set serverbind = "127.0.0.1" in its configuration, or put it behind access control, before exposing the port.

Installation and configuration ↗
Bitcoin Core
On mainnet, with server=1 and RPC credentials, and its blk*.dat files local and complete from genesis: not a pruned node.
The first index
Takes hours. More than 10,000 blocks behind, Bitview catches up before it starts serving.
Configuration
Settings that persist live in ~/.bitview/config.toml.

What it serves

Studio and the API, from your own node, as bitview.space serves them; clients and an MCP adapter on top.

Studio↗

Charts of any series: overlaid, stacked, derived with formulas, kept and shared.

The API↗

Series as JSON or CSV; blocks, transactions, addresses and the mempool as JSON; signed transactions relayed. Documented from its own OpenAPI specification.

Generated clients↗

Rust, JavaScript, Python and command-line clients, generated from the server's catalog.

An MCP adapter↗

A separate, stateless service, run beside the server, whose tools are the API's read-only operations. bitview.space's is at mcp.bitview.space, with no account.

Built from plugins

Plugins are ordinary Rust crates, joined into one typed graph when it's compiled: no loader at run time and no plugin ABI to keep stable.

  1. Bitcoin Corevalidates blocks and picks the active chain
  2. BRKreads Bitcoin Core's data
  3. Bitview's pluginsstore indexes and compute the series
  4. Studio and the APIserve them over HTTP
