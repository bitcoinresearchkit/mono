Bitcoin's data, on your own node.

Bitview reads every block from your Bitcoin Core and measures it: prices, supply, holders, miners, fees and thousands more series. Then it serves them to Studio, an HTTP API, generated clients and assistants. bitview.space is the public instance, the same server.

01

Run it

One executable: the official plugins, Studio and the API, beside your node.

Install, or update
$ rustup update && RUSTFLAGS="-C target-cpu=native" cargo install --locked bitviewd$ bitviewd
Bitcoin Core
Mainnet, with server=1 and RPC credentials, and its blk*.dat files complete from genesis (not pruned).
Machine
Linux or macOS, 16 GB of memory recommended, and about 290 GiB of disk on top of Bitcoin Core's.
First index
About an hour and a half on a 16 GB Mac mini with a fast SSD; slower disks and CPUs take longer. When more than 10,000 blocks behind, Bitview catches up before it starts serving.
Configuration
~/.bitview/config.toml, edited by hand; the install command updates the executable only.

It listens on 127.0.0.1:3110, this machine only, without authentication. To serve your network, set serverbind = "0.0.0.0" in the configuration, behind access control.

02

What it serves

The same data, however you work: charts, plain HTTP, a client in your language, or an assistant.

Studio →

Chart any series: overlay, stack in panes, derive with formulas, then keep, share or export.

HTTP API →

Series as JSON or CSV; blocks, transactions, addresses and the mempool as JSON; OpenAPI documentation.

Generated clients →

Rust, JavaScript, Python and a command line, generated from the server's own catalog.

For assistants →

A stateless MCP server whose tools come from the read-only API, at mcp.bitview.space, no key needed; or hand one llms.txt.
03

How it's built

Plugins are plain Rust crates, put together into a typed graph at compile time: no dynamic loading, no plugin ABI. Bitview's own are the default; yours join them.

  1. Bitcoin Coreon your node: validates, picks the chain
  2. Bitcoin Research Kitreads its blocks, RPC and mempool
  3. Pluginsindex and compute every series; yours beside Bitview's own
  4. ServeStudio, the API, clients
// A plugin: its storage, and what it keeps. (From the custom plugin example.)
#[derive(Traversable, Plugin)]
#[plugin(storage = STORAGE)]
pub struct Vecs<M: StorageMode = Rw> {
    #[traversable(skip)]
    db: Database,

    /// Consecutive blocks at least 90% of the maximum weight.
    streak: M::Stored<PcoVec<Height, Count>>,
}

// The binary: Bitview's runner, your composition.
fn main() -> Result<()> {
    run(Plugins::import)
}

The whole example adds one series to Bitview's defaults and serves it through the same API.
