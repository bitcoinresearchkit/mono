Bitview

Support

Last updated November 11, 2026

For help with bitview.space and mcp.bitview.space, email or open an issue; security problems go by email only. A Bitview server at another address is run by someone else: ask them, and report bugs in the software itself on GitHub.

Is bitview.space up and current? /health and /api/server/sync show its uptime and how far it is from the chain's tip.

Email

Write to support@bitview.space for questions, anything private, rights notices and content reports. For a problem, include:

  • what you used: a page and your browser, an API endpoint, or an MCP tool and your AI assistant's name and version;
  • the address you used: bitview.space, mcp.bitview.space or another;
  • what you did and what came back, with the exact error;
  • roughly when, with your time zone.

Never send a private key, seed phrase, wallet descriptor or extended public key, or anything private the problem doesn't need. How email is kept is on the privacy page.

Bug reports and feature requests

Open an issue on GitHub; for a bug, with the same details as an email. It needs a GitHub account and is public, so keep private details to email.

Security problems

Email support@bitview.space with what you found and how to reproduce it. Good-faith reports are welcome, and the terms don't count them as an attack. Run tests and load only against your own Bitview server, never against bitview.space or mcp.bitview.space: the terms don't allow attacking or overloading them.

Are there limits?

There's no API key or payment, and no fixed request limit is published. Size caps you may meet:

  • weight_exceeded: a series request asked for too much at once. Ask for a shorter range (start, end) or a less detailed index, such as daily (day1).
  • too_many_utxos: the address has more than 500 unspent outputs to list. On your own server, the cap is a setting (maxutxos).
  • Through the MCP server, an answer over 8 MiB fails: ask for a shorter range.

To protect the services, access may be slowed, limited or blocked, as the terms say. For heavy or constant use, run your own server.

What does a series mean?

A series is one measurement over blocks or time, such as the realized price. The Catalog shows every series: what it is, the intervals it comes in and how to fetch it.

Through the API, a series' description is at /api/series/{id}, and /api/series/search?q=realized+price finds one by plain words. Through MCP, use the tools get_series_info and search_series.

A wrong id or index is refused with the nearest ids or the valid indexes, and Changes lists every id renamed or removed.

Why does a number look wrong?

In values from the API or MCP, check these first:

  • end is exclusive: one block is start 900000, end 900001; one day is start 2025-01-01, end 2025-01-02.
  • A Ratio or Multiple is a plain number (0.55, not 55%); a Percent is already a percent (55 means 55%).
  • null means missing or undefined (before the data exists, or a period with no block), never zero.
  • price reads 0, not null, before block 74,641 (August 2010): there was no price yet.

Bitview computes its on-chain data itself, so numbers can differ from other sites. Since block 340,000 (January 2015), the price is estimated from the chain, not taken from an exchange; the terms list the earlier price sources. A day's price is its last block's, so today's price changes until the day ends. Past values can be revised when recent blocks are replaced, a method improves or a mistake is fixed.

Still wrong? Email or open an issue with the series id, the index, the date or block height, the value you saw, and what you expected and from where.
