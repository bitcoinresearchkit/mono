Rust crates for Bitcoin Core data

Bitcoin Core RPC, block files read in chain order, the live mempool, BTC prices read from the chain, domain types and indexed storage, each its own crate. Use one, or combine what a program needs.

Crates

Add the one closest to what your program does. Each opens its documentation; source and examples are in the repository.

Bitcoin Core's data

brk_rpc↗

Calls Bitcoin Core's JSON-RPC with typed results, retrying while the node is out of reach.

brk_reader↗

Streams the chain's blocks from the local blk*.dat files, orphans skipped.

brk_mempool↗

Keeps the mempool live: its projected blocks and fee recommendations.

Prices and foundation

brk_oracle↗

Estimates BTC/USD at every block from 2015 on from the chain's transaction outputs, exchange prices bundled for the blocks before.

brk_types↗

Bitcoin's domain types, and the indexes they're stored by.

brk_store↗

Typed key-value storage over fjall.

And the crates they share: brk_error, brk_logger and brk_alloc.

Read the chain's height

A whole program, on brk_rpc's default RPC address and cookie file. Bitcoin Core must be running with RPC on.

Add it
$ cargo add brk_rpc
src/main.rs
use brk_rpc::ConnectArgs;

fn main() {
    let rpc = ConnectArgs::default()
        .client()
        .expect("connect to Bitcoin Core");
    let height = rpc.get_last_height().expect("read chain tip");
    println!("{height}");
}

Where it stops

Bitcoin Core validates the chain and picks the active one. BRK reads and organizes the data of a node you configure; it doesn't implement consensus.

Bitview is one application built on these crates.

In active development

Public APIs and storage formats may change between releases. Every crate shares one version, so related ones update together. Follow the releases, or report an issue.
