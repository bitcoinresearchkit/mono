Rust crates for Bitcoin Core data.

Bitcoin Core RPC, its block files in chain order, the live mempool, a price read from the chain, Bitcoin's types and typed storage: each its own crate. Use one, or the parts you need; Bitview is built from all of them.

Bitcoin Core data

brk_rpc

Calls Bitcoin Core's JSON-RPC with typed results, retrying while the node is out of reach and refreshing its cookie.

cargo add brk_rpc
brk_reader

Streams the blocks in your node's blk*.dat files in canonical chain order, skipping orphans.

cargo add brk_reader
brk_mempool

Keeps the live mempool, its projected next blocks and fee recommendations.

cargo add brk_mempool

Prices and foundation

brk_oracle

The BTC/USD price of each block from its round-dollar outputs, from 2015 on, with exchange prices bundled for the blocks before. No feed.

cargo add brk_oracle
brk_types

Bitcoin's domain types and storage indexes, shared by every crate here and by Bitview.

cargo add brk_types
brk_store

Typed key-value stores over fjall, with version checks and batched ingestion.

cargo add brk_store

Support

brk_error
The errors used throughout.
brk_logger
Tracing set up, with daily and per-level log files.
brk_alloc
mimalloc, re-exported, with eager memory collection.
brk_exit
On Ctrl-C or SIGTERM, waits for guarded sections to finish, runs cleanup, then exits.
02 · An example

Connect to Bitcoin Core

brk_rpc

Read the chain's height

A complete program, using brk_rpc's default RPC address and cookie file. Bitcoin Core must be running with RPC enabled.

cargo add brk_rpc
use brk_rpc::ConnectArgs;

fn main() {
    let rpc = ConnectArgs::default()
        .client()
        .expect("connect to Bitcoin Core");
    let height = rpc.get_last_height().expect("read chain tip");
    println!("{height}");
}

Where it stops. Bitcoin Core validates every block and picks the active chain. BRK reads and organizes what a configured node has; it is not a consensus implementation.
