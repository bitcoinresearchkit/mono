Rust crates for Bitcoin Core data.

The workspace is split into crates for Bitcoin Core RPC, canonical block-file reading, block iteration, live mempool state, BTC prices, domain types, and indexed storage. A program can use one crate or combine the parts it needs.

Crates

Add the crate closest to the operation your program needs. Each name links to its API documentation; source, examples, and longer notes are in the repository.

Bitcoin Core data

brk_rpc

Calls Bitcoin Core JSON-RPC with typed results and configurable retries.

 brk_reader

Streams canonical blocks from local blk*.dat files and skips orphans.

 brk_iterator

Iterates block ranges through RPC or raw-file reading.

 brk_mempool

Maintains live mempool state, projected blocks, and fee recommendations.

BTC prices

brk_fetcher

Fetches daily and per-block OHLC with source fallback.

 brk_oracle

Estimates BTC/USD per block from transaction-output patterns, without exchange data.

Foundation

brk_types

Bitcoin domain and storage-index types.

 brk_store

Typed key-value storage over fjall.

Support crates: brk_error, brk_logger, and brk_alloc.

Connect to Bitcoin Core

This complete program uses brk_rpc's default Bitcoin Core RPC address and cookie-file path.

brk_rpc

Read the chain height

Bitcoin Core must be running with RPC enabled.

cargo add brk_rpc
use brk_rpc::{Auth, Client};

fn main() {
    let datadir = Client::default_bitcoin_path();
    let rpc = Client::new(
        Client::default_url(),
        Auth::CookieFile(datadir.join(".cookie")),
    )
    .expect("connect to Bitcoin Core");

    let height = rpc.get_last_height().expect("read chain tip");
    println!("{height}");
}
Project boundary Bitcoin Core performs consensus validation and identifies the active chain. BRK reads and organizes data from a configured node; it is not a consensus implementation. Bitview is one application built with these libraries.

Active development

Public APIs and storage formats may change between releases. Workspace crates share one release version so related dependencies can be updated together.
